01 ARQUITETURA DE INFRAESTRUTURA & STACK

1.1 Visão Geral da Topologia Híbrida

A plataforma adota uma estratégia moderna de computação híbrida e serverless:

  • Ambiente de Desenvolvimento Local: Servidor Node.js 20+ com framework Express 5.x, utilizando CommonJS canônico e pool de conexões mysql2/promise integrado com o cluster gerenciado TiDB Cloud (compatível com MySQL 8.0, SSL TLS 1.2).
  • Ambiente de Produção Global (Cloudflare Edge): A aplicação é servida como SPA estática ultrarrápida via Cloudflare Pages CDN, e todo o backend REST /api/v1/* é executado na borda (Edge Functions) sobre V8 Isolates no arquivo functions/api/[[catchall]].js, persistindo no Cloudflare D1 (SQLite distribuído com replicação geográfica automática).

02 INSTALAÇÃO, MIGRAÇÕES & SEEDING LOCAL

2.1 Procedimento de Instalação Passo a Passo

  # 1. Clonar o repositório oficial
  git clone https://github.com/higorsdds-bot/Senai-porto.git
  cd Senai-porto

  # 2. Instalar dependências de runtime e auditoria
  npm install

  # 3. Criar e configurar o arquivo .env
  cp .env.example .env
  # (Editar .env com as credenciais válidas do TiDB Cloud e JWT_SECRET)

  # 4. Executar a migração DDL de criação de tabelas
  node src/database/migrate.js

  # 5. Executar o seed idempotente (criação de setores, 42 permissões e 15 perfis)
  node src/database/seed.js

  # 6. Iniciar o servidor Express em modo de desenvolvimento
  npm run dev
  # Servidor disponível em http://localhost:3000

2.2 Migrações e Índices no Cloudflare D1 (Produção)

No ambiente Cloudflare Pages, a função functions/api/[[catchall]].js executa de forma assíncrona e autocontida a rotina ensureDbInit(db) no primeiro cold start do isolate, criando automaticamente os seguintes índices de alta performance:

  • idx_ocorrencias_del_created ON ocorrencias(deleted_at, created_at DESC)
  • idx_ocorrencias_status ON ocorrencias(status, deleted_at)
  • idx_equipamentos_del ON equipamentos(deleted_at)
  • idx_usuarios_del ON usuarios(deleted_at)
  • idx_comunicados_del ON comunicados(destinatario_perfil, deleted_at)

03 PIPELINE DE IMPLANTAÇÃO (CI/CD) & WRANGLER

3.1 Deploy via Wrangler Pages CLI

A publicação do projeto na nuvem da Cloudflare é realizada de forma contínua via linha de comando:

  # Publicação em produção no alias oficial (main)
  npx wrangler pages deploy . --project-name=hub-es-secult --branch=main

O processo compila a árvore estática de assets, empacota as Edge Functions e despacha o bundle para os data centers globais da Cloudflare em aproximadamente 3 a 5 segundos, gerando um endereço imutável de pré-visualização e roteando para o alias definitivo https://main.hub-es-secult.pages.dev.

3.2 Vinculação do Banco D1 no Painel da Cloudflare

No painel do Cloudflare Pages (Settings > Functions > D1 database bindings):

  • Variable Name: DB (Obrigatório, nome esperado pelo código).
  • D1 Database: Selecionar a base de dados provisionada para o projeto (ex: hub-es-secult-db).

04 GOVERNANÇA, HEARTBEAT & AUDITORIA MASTER

4.1 Monitoramento de Usuários Online (Heartbeat)

A cada 60 segundos, os navegadores dos colaboradores autenticados disparam uma requisição silenciosa POST /api/v1/auth/heartbeat. O backend atualiza a coluna ultimo_heartbeat = datetime('now'). No módulo administrativo em #auditoria, a rota /api/v1/auditoria/usuarios-online lista em tempo real todos os colaboradores com pulso nos últimos 5 minutos, garantindo total transparência sobre quem está operando no sistema.

4.2 Trilha de Auditoria Imutável (Append-Only)

A tabela auditoria armazena todos os registros de escrita e autenticação. Ela é blindada contra modificações ou exclusões. As consultas suportam filtros por período de datas, usuário, ação e tipo de entidade para auditorias de conformidade do Tribunal de Contas (TCE-ES).
